Claims Coverage Assessment Assistant

An AI assistant that reviews an insurance claim against policy documents and returns a structured coverage decision — coverage outcome, supporting policy clauses, a confidence score, a fraud risk assessment, and a flag for cases needing human review. Built as a tool-calling LLM agent backed by RAG and four tools exposed over MCP, running on a single FastAPI service.

FastAPI OpenAI / Azure OpenAI RAG (embeddings + cosine similarity) MCP (Model Context Protocol) MongoDB / Cosmos DB vCore Single container API Docs →

Architecture Overview

POST /claims/assess │ ▼ Agent Orchestrator (LLM tool-calling loop) │ real MCP client, loopback HTTP only ▼ MCP server, mounted at /mcp (external access blocked) │ ├─ retrieve_policy_clauses (RAG) ├─ lookup_claim_history (excludes current claim) ├─ check_coverage_rules (deterministic, no LLM) └─ score_fraud_risk (deterministic, no LLM) │ ▼ MongoDB (product_versions / issued_policies / claims)

Key design choices:

  • One process, one container — MCP is mounted in-app, not a separate service
  • Agent is a genuine MCP client, not a direct function-call shortcut
  • Coverage rules and fraud scoring are deterministic code — never an LLM decision
  • Product catalog (rules/wording) kept separate from each customer's issued policy
  • Claim history is a query over the same claims collection, not a separate store

Features

  • Tool-calling AI agent (OpenAI / Azure OpenAI function-calling)
  • RAG retrieval over policy clauses (OpenAI embeddings + cosine similarity)
  • Model Context Protocol (MCP) server exposing 4 reusable tools
  • MCP endpoint restricted to loopback — not reachable externally
  • Deterministic, auditable coverage rule engine
  • Transparent, weighted fraud risk heuristic (signals fully explained)
  • Fraud result always sourced from the tool output, never LLM retelling
  • Graceful fallback decision assembly if the LLM's output is malformed
  • Product-version / issued-policy schema (no duplicated rules per customer)
  • Claim lifecycle tracking: submitted → under_review → approved / rejected
  • API key protected write endpoint (X-API-Key)
  • Structured JSON logging, typed exceptions, input validation
  • 25+ automated tests — unit, integration, and a real MCP protocol round trip
  • Single Docker image — deployable to Azure Container Apps via GitHub Actions
